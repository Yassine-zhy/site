# Étape 20 — Une base de données en ligne : les comptes survivent aux redémarrages

> **Objectif :** en ligne, que les comptes, favoris, portefeuilles et alertes soient **conservés**. Sur
> l'hébergement gratuit de Streamlit, le disque est effacé à chaque redémarrage (mise à jour du code, mise en
> veille) : le fichier SQLite disparaît avec. La solution : une base **PostgreSQL** hébergée gratuitement (Neon ou
> Supabase), indiquée par une seule ligne dans les secrets. Sans cette ligne, rien ne change : SQLite en local.

Fichiers modifiés : `core/storage.py`, `app.py`, `views/settings.py`, `requirements.txt`,
`.streamlit/secrets.toml.example`, `tests/conftest.py`, `tests/test_storage.py`, `tests/test_app.py`.

---

## 1. Pourquoi PostgreSQL ?

| | SQLite | PostgreSQL |
| --- | --- | --- |
| Où sont les données | un fichier sur le serveur de l'appli | un serveur de base de données séparé |
| Survit au redémarrage de l'appli en ligne | ❌ (disque effacé) | ✅ |
| Installation | aucune (fournie avec Python) | un compte gratuit chez un hébergeur |
| Idéal pour | ton ordinateur, les tests | le site en ligne, plusieurs visiteurs |

PostgreSQL est la base libre la plus utilisée par les entreprises. Neon et Supabase en proposent une gratuitement
(environ 0,5 Go : des centaines de milliers de favoris).

---

## 2. Créer la base (5 minutes)

### Option A — Neon (recommandé : se réveille tout seul)

1. Va sur <https://neon.tech> → **Sign up** (avec GitHub ou Google).
2. **Create project** : nom `finveille`, région **Europe (Frankfurt)** → *Create*.
3. Sur le tableau de bord du projet : **Connect** → copie la *connection string* :
   ```
   postgresql://neondb_owner:MOT-DE-PASSE@ep-xxxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```

La base s'endort après quelques minutes sans visite et se réveille automatiquement à la première requête (une
seconde de plus au premier affichage).

### Option B — Supabase

1. Va sur <https://supabase.com> → **Start your project** (connexion avec GitHub).
2. **New project** : nom `finveille`, choisis un **mot de passe de base de données** (note-le), région
   **West EU (Paris)** → *Create new project*.
3. Bouton **Connect** en haut de la page → onglet *Connection string* → choisis **Session pooler** (et pas *Direct
   connection* : Streamlit Community Cloud ne sait pas joindre l'adresse IPv6 de la connexion directe) :
   ```
   postgresql://postgres.abcdefgh:MOT-DE-PASSE@aws-0-eu-west-3.pooler.supabase.com:5432/postgres
   ```
4. Remplace `[YOUR-PASSWORD]` par ton mot de passe.

Sur l'offre gratuite, un projet Supabase sans aucune visite pendant une semaine est mis en pause : un clic sur
*Restore* dans le tableau de bord le relance (les données sont conservées).

## 3. La brancher sur FinVeille

Dans `.streamlit/secrets.toml` (en local) **et** dans *Settings → Secrets* de l'appli sur Streamlit Community Cloud,
ajoute **avant** la section `[auth]` :

```toml
DATABASE_URL = "postgresql://neondb_owner:MOT-DE-PASSE@ep-xxxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require"
```

Redémarre l'appli. Au premier affichage, `storage.init_db()` crée les tables. Vérifie dans *Réglages → Mes
données* : « Tes données sont enregistrées dans une base PostgreSQL en ligne ». Tu peux aussi voir les tables dans
l'éditeur de Neon (*Tables*) ou de Supabase (*Table Editor*).

> ⚠️ Si ton mot de passe contient des caractères spéciaux (`@`, `:`, `/`, `#`…), ils doivent être **encodés**
> dans l'adresse : `@` → `%40`, `#` → `%23`, `/` → `%2F`. Le plus simple : régénère un mot de passe sans ces
> caractères.

## 4. Ce qui a changé dans le code

### Une seule fonction `connect()`, deux bases

```python
@contextmanager
def connect():
    if backend() == "postgres":
        with _postgres_pool().connection() as conn:   # valide à la sortie, annule en cas d'erreur
            yield _PostgresConnection(conn)
        return
    conn = sqlite3.connect(DB_PATH, timeout=10)        # comme avant
    ...
```

Toutes les autres fonctions (`add_follow`, `list_favorites`…) n'ont pas changé : c'est l'intérêt d'avoir rangé
tout le SQL dans `core/storage.py` dès l'étape 3.

### Du SQL commun aux deux bases

| Avant (SQLite seulement) | Après (SQLite et PostgreSQL) |
| --- | --- |
| `INSERT OR IGNORE INTO follows …` | `INSERT INTO follows … ON CONFLICT DO NOTHING` |
| `INSERT OR REPLACE INTO settings …` | `INSERT INTO settings … ON CONFLICT (user_id, key) DO UPDATE SET value = excluded.value` |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `{auto_id}` remplacé selon la base (`BIGINT GENERATED BY DEFAULT AS IDENTITY` en PostgreSQL) |
| `REAL` (4 octets en PostgreSQL : des centimes perdus !) | `DOUBLE PRECISION` (8 octets dans les deux) |
| `….fetchone()[0]` | `SELECT COUNT(*) AS n …` puis `….fetchone()["n"]` |

La seule différence restante, l'écriture des paramètres (`?` pour SQLite, `%s` pour psycopg, la bibliothèque
PostgreSQL), est traduite par la petite classe `_PostgresConnection`.

### Une réserve de connexions

Ouvrir une connexion chiffrée vers un serveur distant prend 100 à 300 ms. Une page appelle `storage` 5 à 10 fois :
sans précaution, plusieurs secondes d'attente. `psycopg_pool.ConnectionPool` garde quelques connexions **ouvertes**
et les prête à chaque appel. Comme le cache, la réserve est partagée par tous les visiteurs (ce n'est pas une donnée
personnelle).

Deux réglages :

- `row_factory=dict_row` : chaque ligne est un dictionnaire (`row["is_read"]`), comme avec `sqlite3.Row` ;
- `prepare_threshold=None` : les *poolers* de Supabase (PgBouncer) ne supportent pas les requêtes « préparées ».

### `init_db` une seule fois

`app.py` appelle `storage.init_db()` à chaque affichage. Avec une base distante, recréer 8 tables (même déjà là)
à chaque clic coûterait cher : on retient dans `_ready` les bases déjà initialisées par le processus.

## 5. Tester avec une vraie base PostgreSQL

Chaque test de `tests/test_storage.py` utilise la fixture `store`, qui s'exécute **deux fois** : avec SQLite, puis
avec PostgreSQL si une base de test est indiquée :

```bash
FINVEILLE_TEST_DATABASE_URL=postgresql://finveille:finveille@localhost:5432/finveille_test pytest
```

Sans cette variable, les tests PostgreSQL sont simplement **sautés** (`skipped`). Pour avoir un PostgreSQL local :
installe-le depuis <https://www.postgresql.org/download/>, ou avec Docker :
`docker run -e POSTGRES_PASSWORD=finveille -p 5432:5432 postgres:17`.

> ⚠️ N'utilise **jamais** ta base de production pour les tests : la fixture supprime les tables avant chaque test.

## 6. Sécurité et RGPD

- `DATABASE_URL` contient un mot de passe : uniquement dans les secrets, jamais dans le code ni sur GitHub.
- La connexion est chiffrée (`sslmode=require`).
- La base contient des e-mails : la page *Mon compte* permet toujours d'exporter et de supprimer ses données
  (étape 14), et la suppression s'applique maintenant à la base en ligne.

## 8. Erreurs fréquentes

| Symptôme | Cause | Solution |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'psycopg'` | Dépendances pas à jour | `pip install -r requirements.txt`. |
| `connection timeout` / `couldn't get a connection after 15 sec` | Adresse fausse, base en pause (Supabase), ou connexion directe IPv6 | Vérifie l'adresse, relance le projet, utilise le *Session pooler*. |
| `password authentication failed` | Mot de passe faux, ou caractère spécial non encodé | Encode `@ : / #`, ou régénère le mot de passe. |
| `prepared statement "_pg3_0" already exists` | Pooler en mode transaction de Supabase | `prepare_threshold=None` (déjà réglé). |
| Les données disparaissent toujours | `DATABASE_URL` absent des secrets **en ligne** | Ajoute-le dans *Settings → Secrets* de Streamlit Cloud ; vérifie la ligne dans *Réglages*. |
| `syntax error at or near "OR"` | Une requête `INSERT OR …` propre à SQLite | Utilise `ON CONFLICT …`, compris par les deux bases. |
